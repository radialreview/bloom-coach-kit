  extension (their real logged-in browser) and suggests 2–3 people worth a call, with a
  drafted opener each. **Constraints that shape it:** attended sessions only — browser
  automation is the fragile class the Command Deck deliberately excludes from unattended
  runs, and LinkedIn actively fights automation, so this stays a coach-present,
  read-and-suggest specialist, never a scheduled scraper and never an auto-messenger
  (draft-never-send applies doubly here). Demo-first candidate for the outreach webinar.
- **Call logging loop** — coach says "log my calls: reached Dana, left a message for Sam";
  assistant writes them to notes; the brief's nudge shows streak and gaps. Zero new

## Notes schema v1 — the memory dir becomes a knowledge graph

**SHIPPED 0.4.0** (pulled forward from post-workshop — shipping before any coach installs
means zero migrations ever, and Friday's dry run exercises it). One concept per file —
`clients/`, `sessions/` — with minimal frontmatter (`type`, `title`, `updated`,
`stale_after`) and `[[wikilinks]]`; `about-my-coach.md` stays the hub because the CLAUDE.md
activation and the brief's task prompt read it by path. The conventions make the dir
OKF-conformant (GoogleCloudPlatform/knowledge-catalog v0.2) as a side effect and openable
as an Obsidian/Logseq vault directly. Eval A7 covers it.

**Schema v1.1, SHIPPED 0.6.0: checked against the spec itself.** In 0.4.0 conformance was a
side effect, never actually tested. On 2026-09-24 it was, against SPEC.md v0.2 (now at
GoogleCloudPlatform/open-knowledge-format; the knowledge-catalog copy is a frozen snapshot).
The minimal core held up: `type` on every note is the whole of conformance. What didn't hold
were the places the kit used spec-defined fields the wrong way:
- `stale_after` was a bare date. The spec says every timestamp is ISO 8601 with a UTC offset,
  and comparing a bare date against a datetime throws in most parsers.
- `status` was carrying work state (`active`, `open`, `done`), but OKF reserves it for
  `draft | stable | deprecated`. Renamed to `state`, and the readers still accept the old key.
- Unquoted values broke parsing. A colon inside a title, or a bare `[[name]]` (which YAML reads
  as a nested list). Real notes in Mike's live Dex had both.
- `description` was missing. It's a recommended field and costs one line, and the hub's
  pointer line now reuses it, so it gets written once.

Deliberately not changed: `[[wikilinks]]` stay, rather than the spec's markdown links, because
they resolve by name and survive a note moving folders. `updated` stays, rather than
`generated: { by, at }`.

**Still phase-two:** the session-recap specialist as the graph's main feeder; richer OKF
provenance (`generated by`, `verified`) if agent-vs-human attribution ever matters; a
`log.md` daily journal if Mike's Logseq-replacement experiment says journals are the
missing piece.

## Voice, the loop that learns from edits

`learn-my-voice` (v1) learns from what the coach already sent, and from corrections they say out
loud. It does **not** learn from the edits they make to the assistant's own drafts, which is the
strongest signal there is. Why it isn't built: a draft handed back in chat leaves no trace, and a
draft saved to the mailbox disappears into Sent once it goes out, so there is nothing to diff
against. Two ways to make it observable, both with a cost:

- **A drafts ledger.** The drafters append date, recipient, subject and body to a note when they
  hand a draft over; a weekly task finds the matching sent message and writes the differences into
  the voice note's Corrections. Cost: client email bodies sitting in memory, and a write on every
  draft by an agent that is meant to be read-only on the coach's files. Decide that deliberately.
- **A mailbox-draft convention.** The persona saves every draft to the coach's drafts folder, and
  the task compares what was saved with what went out. Cost: it only works where the connector can
  save drafts, and matching a draft to its sent version is by subject and recipient, which is
  heuristic.

Also banked: a scheduled **drift check** (re-sample the last month of sent mail against the note
and say where it has stopped being true), a second voice per person for a side business without
blending the two, and the Outlook path, which needs testing on a real Microsoft 365 mailbox.

## Time-blocking, generally

The scheduler already flags crowding; the inverse — proactively **reserving** blocks
(calls, prep, deep work) — is a natural scheduler upgrade. Constraint: propose-never-book
stays absolute; the specialist drafts the calendar holds, the coach confirms. Candidate for
the same outreach webinar as the growth-calls material.
